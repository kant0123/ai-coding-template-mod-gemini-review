# Wiki の健康診断 (Lint)

> **このファイルはテンプレートです。** Wiki を採用しないなら、このスキルごと削除してよい。
> Claude Code で使う場合は `.claude/skills/wiki-lint/SKILL.md` に置く。

**エージェントは 1 ページ内で完結する局所ルール(frontmatter を書く、テンプレートに従う)はよく守るが、
Wiki 全体にまたがる大域的な一貫性は自然には保てない。** 壊れるのは常に後者なので、機械で判定できる
ものは機械に見張らせ、意味の理解が要るものだけをエージェントが見る。

| 検査 | 担当 |
| --- | --- |
| 壊れた `[[リンク]]`(`index.md` の「未作成ページ」に控えの無いもの) | `scripts/wiki-lint.js` |
| 孤立ページ・`index.md` の掲載漏れ | `scripts/wiki-lint.js` |
| frontmatter の不備・`type` と置き場所の不一致 | `scripts/wiki-lint.js` |
| `updated` と最終コミット日のズレ・`related` の片方向参照 | `scripts/wiki-lint.js` |
| コード参照(`path:line 記号名`)のファイル実在・行のズレ | `scripts/wiki-lint.js` |
| 参照先コードがページより後に変更されている(注意止まり) | `scripts/wiki-lint.js` |
| `index.md` のカタログと各ページの `summary` の食い違い | `scripts/wiki-lint.js` |
| 矛盾するページ | エージェント |
| コードと乖離した記述 | エージェント |
| 言及されるのにページが無い概念 | エージェント |

## 1. 機械検査を通す

```bash
node scripts/wiki-lint.js       # package.json があれば npm run wiki:lint
```

意味の検査は機械側が通っていることが前提。エラーがあれば先に直す。

- `updated` の判定は git の最終コミット日を見るので、**コミット前に走らせると古い日付で落ちる。**
- ページを足したり `summary` を直したら `--write-index` を付けてカタログを再生成する。
- **注意(`注意:` で始まる行)は CI を落とさないが読む。** 特に「参照先が更新されている」は、
  そのページの記述が古くなっていないかを手順 2 で確かめる候補になる。

CI で回すには `.github/workflows-optional/wiki-lint.yml` を `.github/workflows/` にコピーする
(デプロイが待つテストのワークフローには相乗りさせない)。

## 2. 意味の検査をする

- **コードと乖離した記述** — ページが参照するコード・テスト・ログと突き合わせる。
  手順 1 の「参照先が更新されている」注意が出たページから当たる。
- **矛盾するページ** — 同じ対象を扱うページ同士(`related` で繋がるもの、同じコードを参照するもの)を
  読み比べる。
- **言及されるのにページが無い概念** — 複数ページの本文に出てくるのに、独立したページも
  「未作成ページ」の控えも無いもの。

## 3. 矛盾を 2 種類に分けて扱う

| 種類 | 例 | 扱い |
| --- | --- | --- |
| コード・テスト・ログと突き合わせて**再導出できる**乖離 | Wiki が「既定 15 分」と書いているがコードは 20 分 | Wiki を直す。依頼を待たない(「コードが正、Wiki が従」の延長) |
| ページ間の**散文的な**矛盾 | 2 ページが別々の理由付けを述べていて、どちらが今の判断か解釈が要る | **勝手に統合しない。**両論を残したまま人間に判定を渡す |

後者を自分の判断で片方に寄せると、消えた側の根拠ごと失われる。さらに「矛盾していた」という
判断自体が後のセッションから事実として読まれるため、**推測を記録に昇格させない**。

## 4. 直して報告する

修正はコミットを伴うので、通常の開発フロー(`worktree-start` → `pr-finish`)で行う。
`wiki/log.md` には種別 `lint` で 1 件追記する。

```markdown
## [YYYY-MM-DD] lint | <一行要約>
- 更新: [[page-a]]
- 発見: [[page-b]] と [[page-c]] で〜の理由付けが食い違う(未判定・人間の判断待ち)
```

報告には、直したもの・人間の判定を待つ矛盾(両ページの該当箇所つき)・新しく書くべきページの候補を
分けて書く。
