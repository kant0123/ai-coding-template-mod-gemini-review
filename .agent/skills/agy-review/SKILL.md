# agy レビュー — CI 緑の後、マージの前

> **このファイルはテンプレートです。** 採用しない場合は `review/` ごと削除する。
> Claude Code で使う場合は `.claude/skills/agy-review/SKILL.md` に置く。

仕組みの説明は [review/README.md](../../../review/README.md)。ここには手順だけ書く。

```
push → CI ─緑→ agy レビュー ─APPROVE→ merge
        ↑            │
        │       CHANGES_REQUESTED
        │            ↓ 指摘を 1 件ずつ評価
        └─ 修正 ←─ 妥当な指摘がある
                     すべて的外れ → 上流に起票 → 評価を記録 → merge
```

## 1. CI が緑になってからレビューする

```bash
gh pr checks <PR番号> --watch
python review/agy_review.py --pr <PR番号>
```

スクリプトは CI が緑でなければ実行を拒否する(exit 2)。テストで落ちる差分をレビューしても
修正で差分が変わるので無駄になるため。

結果は PR コメントに投稿され、標準出力にも出る。**head SHA ごとに記録される**ので、
push するたびに「未レビュー」に戻る。

| 終了コード | 意味 | 次にやること |
| --- | --- | --- |
| 0 | APPROVE(指摘なし、または NITPICK のみ) | `pr-finish` に戻ってマージ |
| 3 | CHANGES_REQUESTED(CRITICAL か WARNING がある) | 手順 2 |
| 2 | CI が緑でない | CI を直す |
| 1 | agy / gh の失敗 | エラーを読んで再実行。**レビューを飛ばしてマージしない** |

NITPICK は採否を自由に決めてよく、記録も要らない。

## 2. 差し戻しを評価する

CRITICAL / WARNING を **1 件ずつ**、実際のコードと突き合わせて判定する。
agy は差分と関連 Wiki に加えて head 時点のスナップショットを読めるが、どのファイルを開いたかは
agy 次第なので、差分の外にある前提を知らずに指摘していることがある。PR コメントの「参照した資料」で
開いたファイルと、**開かれなかった変更ファイル**を確かめてから判定する。

| 判定 | 基準 | やること |
| --- | --- | --- |
| 妥当 | 指摘の機序が実際に起きる | 修正する |
| スコープ外 | 妥当だが今の PR で直すと肥大化する | Issue をこのリポジトリに起票する(`CLAUDE.md`「スコープ外の問題を発見したとき」) |
| 誤検知 | 指摘の機序が成立しない(差分の外で既に防がれている、前提が事実と違う等) | 手順 4 で上流に起票する |

**自分のコードを庇う方向に判定を倒さない。** 誤検知と判定するなら、成立しない理由を
コードの場所つきで書けること。書けないなら妥当として扱う。

## 3. 妥当な指摘が 1 件でもあれば — 修正ループ

直す場所まで戻って修正する。設計から見直しが要るなら実装に、テストが足りないならテストに戻る。

**修正は指摘の failure_scenario を実際に再現する形にする。** 症状に触れない箇所(テスト名・
コメント等)だけ変えて済ませない。再レビューの APPROVE は「その症状を再現するテストで
確認した」ことの代わりにはならない — agy は新しい差分を見て新たに判定するだけで、
元の指摘が実際に塞がれたかは見ていない。

```bash
# worktree で修正・コミット
git push
gh pr checks <PR番号> --watch
python review/agy_review.py --pr <PR番号>   # 新しい head に対して再レビュー
```

評価の記録は不要(新しい head には新しいレビューが要るので、古い差し戻しは効かない)。
残りの指摘に誤検知が混ざっていたなら、修正と並行して手順 4 の起票はしておく。

## 4. すべて誤検知・スコープ外なら — 起票してマージ

誤検知は**上流(レビュープロンプトの持ち主)**に起票する。起票しないとプロンプトが直らず、
同じ誤検知が全プロジェクトで再発する。

```bash
gh issue create --repo kant0123/gemini-review --label false-positive \
  --title "<誤検知の症状を一文で>" \
  --body "<指摘の本文 / 該当コード / 指摘の機序が成立しない理由 / 使ったモデル / PR の URL>"
```

評価を PR に記録する。記録が無いと merge hook がマージを差し止める。

```bash
python review/agy_review.py --pr <PR番号> --triage <評価を書いた md ファイル>
```

評価のファイルには指摘ごとに 1 行ずつ書く(scratchpad などリポジトリ外に置く)。
**誤検知の行には、起票した上流 Issue の URL を必ず書く。** PR からプロンプト改善の議論に
たどれないと、同じ誤検知が再発したときに既知のものか判断できない。スコープ外の行には起票した Issue 番号を書く。

```markdown
- 1. [CRITICAL] 認可漏れ — 誤検知。`app/routes.py:40 require_owner()` で既に所有者を検証している → https://github.com/kant0123/gemini-review/issues/12
- 2. [WARNING] N+1 — スコープ外。既存の一覧 API 全体の問題 → #58
```

記録したら `pr-finish` に戻ってマージする。

## 5. 見逃しを記録する — 通過した PR に不具合が見つかったとき

不具合を直していて、原因のコードが agy レビューを通過した PR で入ったと分かったら、上流に
`false-negative` で起票する。誤検知だけを記録していると、プロンプトは「指摘を減らす」方向にしか直らない。

起票するのは、**原因が通過した PR の差分に載っていた**場合だけ。差分の外の既存コードが原因のもの、
本番環境でしか分からない事情(外部サービスの挙動・データ量など)によるものは、レビューで
気付けないので起票しない。

```bash
git log -s -L <開始行>,<終了行>:<原因のファイル> --format='%H %s'   # 原因の行を変えたコミット (新しい順)
gh pr list --state merged --search <コミットSHA> --json number,url  # そのコミットを含む PR
python review/agy_review.py --check --pr <PR番号>                   # 通過の記録があるか(exit 0 なら通過)
```

PR コメントの agy レビューが APPROVE だったか、差し戻しを評価してマージしていたかも確かめる。
評価でその指摘を誤検知と判定していたなら、見逃しではなく**評価の誤り**なので、元の誤検知 Issue に
コメントで追記する(新たに起票しない)。

```bash
gh issue create --repo kant0123/gemini-review --label false-negative \
  --title "<見逃した不具合を一文で>" \
  --body "<不具合の Issue の URL / 原因の PR の URL とレビューした head SHA / 使ったモデル / 原因のコード (path:line) / 差分のどこから気付けたはずか>"
```

不具合の Issue(このリポジトリ)には、起票した上流 Issue の URL をコメントで残す。

## PR 本文に書くこと

`pr-finish` の PR 本文テンプレートの「レビュー」節。マージ前に最終結果で更新する。

```markdown
## レビュー

- agy: <APPROVE / 差し戻し N 回 → APPROVE / 差し戻しを評価してマージ>
- 起票: <kant0123/gemini-review#12 (誤検知) / #58 (スコープ外) / なし>
```

## やってはいけないこと

- **CI 緑の前にレビューしない。** スクリプトが拒否する。
- **レビューが失敗(exit 1)したままマージしない。** 出力が空・解釈不能のときは
  APPROVE として記録しない作りになっている。回避手段は置いていない。
- **誤検知の判定を起票せずに済ませない。** チャットに書いただけでは記録に残らない。見逃しも同じ。
- **レポートをコミットしない。** `review/work/` は `.gitignore` 対象。残す価値のある知見は `wiki/` に還元する。
